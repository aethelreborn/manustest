Aethel is a local-first command center. This guide explains the product and the security boundary around each feature.

01 · Vault02 · Bills03 · Focus04 · Security model05 · Account and sync
01

Vault

Vault is for passwords, cards, and private notes. Add an item locally, then use biometric protection before reveal or copy on supported devices.

  • Payloads are encrypted on the device.
  • The API receives encrypted ciphertext and IV, not plaintext secrets.
  • Use the export/re-key flows carefully and keep an independent recovery plan.
02

Bills

Bills turns recurring obligations into a calm timeline. Upcoming, overdue, and paid states use consistent signal colors and labels.

  • Mark paid when an obligation is complete.
  • Use the dashboard for urgency, not a wall of notifications.
  • Keep sensitive payment details in Vault rather than a reminder title.
03

Focus

Focus creates a visible time box for deep work. The current app provides the ritual and countdown; operating-system-level app blocking requires native platform entitlements.

  • Start with 15, 30, 45, 60, or 90 minutes.
  • End a session early when the work is done.
  • Use the schedule language as a commitment, not surveillance.
04

Security model

Firebase Authentication handles Google identity. The Aethel server verifies Firebase ID tokens against Google public keys, then maps the verified UID to a user row in the SQL database.

  • Argon2id derives the local vault key.
  • AES-GCM protects encrypted payloads.
  • SecureStore holds native session and key material where supported.
  • Ownership predicates keep SQL records scoped to the authenticated account.
05

Account and sync

Offline mode is always available for the local product surface. When you sign in with Google, encrypted vault records and the data needed for cross-device continuity can sync to SQL.

  • Sign out from Settings to stop account sync on the device.
  • Use the Privacy Policy for deletion requests.
  • Never include a secret in a support issue.
